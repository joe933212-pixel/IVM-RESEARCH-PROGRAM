# Master Research Chronology

## Phase I — Institutional Computation Problem

The research began with the observation that digital systems execute computation while institutional meaning is often distributed across application logic, databases, identity systems, workflows, audit systems and external authorities.

## Phase II — IVM Concept

The Institutional Virtual Machine emerged as a proposed model in which institutional transitions could become first-class computational objects associated with authority, rules, state, event identity, commitment and history.

## Phase III — Executable Semantics

The work moved from conceptual architecture toward an executable model.

## Phase IV — Reference Runtime

A reference implementation was developed as an experimental instrument.

## Phase V — Runtime Testing

The initial experimental sequence established execution behaviour and exposed assumptions.

## Phase VI — Failure Injection

Controlled failures were introduced to investigate interruption, repetition, duplication and recovery.

## Phase VII — Reference Runtime v0.3

The runtime was tested against progressively stronger failure conditions.

## Phase VIII — Process-Death Question

The research isolated the question: **Can recovery survive actual process death?**

## Phase IX — Reference Runtime v0.4

v0.4 incorporated the changes required to investigate recovery across separate process lifecycles.

## Phase X — IVM Conclusions

The research separated observed implementation properties from architectural interpretations and unresolved questions.

## Phase XI — Prior-Art and Literature Analysis

The research examined relationships with state machines, transaction processing, event sourcing, workflow systems, distributed systems, blockchains, smart contracts, identity and formal methods.

## Phase XII — Section 53

The prior-art analysis reached Section 53, “The Consequence for the IVM Architecture”. The continuation begins at Section 54.

## Phase XIII — Comparative Research

The programme shifted from self-testing to asking whether other execution models could provide the same institutional semantics.

## Phase XIV — Experiment 005

Experiment 005 introduced the canonical transition **PENDING -> ACTIVE** and the comparative semantic vector.

## Phase XV — Conventional State-Machine Comparator

A conventional deterministic state machine is used as the first comparator.

## Current Position

The research has progressed from problem identification to conceptual model, executable semantics, reference runtime, failure testing, process-death recovery, prior-art analysis and comparative execution.

Novelty is not yet established. The programme now has a concrete path for testing that proposition.
